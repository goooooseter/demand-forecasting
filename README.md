# Прогнозирование спроса

Продакшен-готовый ML-микросервис для предсказания ежедневных продаж товаров в розничной сети. Сервис построен на базе **FastAPI** и градиентного бустинга **CatBoost**, упакован в **Docker**.

В основе сервиса лежит полноценное Data Science исследование: от разведочного анализа данных до оптимизации гиперпараметров и интерпретации модели с помощью SHAP.

## Data Science & Machine Learning

Исследование и обучение модели проводилось на датасете demand-forecasting-kernels-only с Kaggle в Google Colab:
[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/drive/13C2VWm6E6F50ukrK_eNdNYTYm8VXFurn#scrollTo=9fmcVNO28Ki8)

**Целевая метрика:** **WAPE** (Weighted Absolute Percentage Error), которая отражает взвешенную абсолютную ошибку модели в процентах:

$$WAPE = \frac{\sum_{i=1}^{n} |y_i - \hat{y}_i|}{\sum_{i=1}^{n} y_i} \times 100\%$$

Где:
* $y_i$ — реальные продажи товара за день,
* $\hat{y}_i$ — предсказанные моделью продажи,
* $n$ — количество наблюдений в выборке.

**Почему именно WAPE?** В отличие от стандартной метрики MAPE, где происходит деление на каждое отдельное значение $y_i$ (что приводит к ошибке или делению на ноль, если в какой-то день продаж не было), WAPE делит сумму абсолютных ошибок на *общую сумму* реальных продаж. Это делает её устойчивой к нулевым дням и идеально подходящей для бизнес-планирования в ритейле.

### 1. Feature Engineering и Валидация
Для предотвращения утечки данных использовался строгий **Time Series Split**: последние 90 дней были отложены в тестовую выборку (45 000 строк).

Были спроектированы следующие признаки:
* **Календарные:** `month`, `year`, `day_of_week`, `is_weekend`. Учет выходных дней оказался критически важен для улавливания паттернов покупок.
* **Скользящие средние:** Рассчитаны средние значения за 7 и 14 дней (`rolling_mean_7`, `rolling_mean_14`), которые стали главными фичами прогноза.
* **Лаги:** В ходе итеративного отбора признаков шумные лаги (за 2 и 3 дня) были удалены, оставлены только наиболее значимые `sales_lag_1` и `sales_lag_7`.

### 2. Моделирование и Optuna
Базовой моделью выступил **CatBoostRegressor**. 
* Наивный бейзлайн показывал ошибку WAPE: **19.83%**.
* Базовая модель CatBoost «из коробки» снизила ошибку до **11.03%**.
* С помощью фреймворка **Optuna** была проведена байесовская оптимизация гиперпараметров, что позволило достичь итоговой ошибки WAPE: **10.97%** на отложенной тестовой выборке.

### 3. Интерпретируемость (SHAP)
Для понимания логики предсказаний был проведен анализ с использованием **SHAP (TreeExplainer)**:
* Анализ показал, что ключевыми факторами для модели являются краткосрочные тренды (скользящие средние) и недельная сезонность (`sales_lag_7`), что подтверждает адекватность модели и её опору на реальные бизнес-закономерности.

## Backend API

Обученная модель (`catboost_demand_model.cbm`) интегрирована в асинхронный REST API.

**Стек технологий:**
* **Python 3.10+**
* **FastAPI** — высокопроизводительный веб-фреймворк.
* **Pydantic** — строгая типизация и валидация входящих JSON-запросов.
* **Docker** — контейнеризация для независимости от окружения.

## Быстрый старт

Вы можете запустить проект двумя способами: в изолированном контейнере (рекомендуется) или локально.

### Вариант 1: Запуск через Docker

1. **Соберите образ:**
   ```bash
   docker build -t demand-api .
   ```

2. **Запустите контейнер:**
   ```bash
   docker run -d -p 8000:8000 --name demand_api_container demand-api
   ```

### Вариант 2: Локальный запуск (venv)

1. **Создайте и активируйте виртуальное окружение:**
   ```bash
   python -m venv .venv
   
   # Для Mac/Linux:
   source .venv/bin/activate  
   
   # Для Windows: 
   .\.venv\Scripts\activate
   ```

2. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

3. **Запустите сервер:**
   ```bash
   uvicorn src.app:app --reload
   ```
